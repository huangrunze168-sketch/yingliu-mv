# 歌词时间来源与复核契约

正式时间不是一个布尔值。原曲、官方歌词、真实识别结果、逐行复核及当前时间轴必须是同一版本；没有这些依据，关1默认失败，后续付费视频生产不能继续。

## 实际识别与待核草稿

`asr_capture.py PROJECT --audio ORIGINAL_AUDIO --lyrics OFFICIAL_LYRICS --model-path LOCAL_MODEL_DIR` 实际调用本地faster-whisper，记录模型二进制、原曲、歌词和入口代码的SHA、引擎版本、运行ID及原始逐词输出。仅使用已存在的指定模型，不自动下载或改写母带。

每次识别使用独立 `analysis/asr_runs/<run_id>/`，旧运行记录归档。原始识别不因官方歌词正确而被悄悄改写。字符匹配候选另外保存；匹配率不代表时间准确率或识别质量。

`timing_draft.py PROJECT` 只消费当前真实识别和匹配结果，建立全部待核的timeline与pending复核模板；缺词、重叠或旧文件存在时失败，不均分时间，不覆盖已存在的时间轴，不将未听辨的空档自动称为间奏。角色标签与原文行号保留，官方歌词仍是文本权威。

## 正式关1要求

- timeline的`timing_source.execution_path`指向当前ASR运行记录，`review_path`指向逐行复核；路径须在项目中。
- 当前原曲/歌词SHA、识别实测时长、运行ID、原始识别SHA以及执行输入须一致。
- 逐行复核绑定当前timeline SHA和当前ASR。每行保留相同的索引、官方文本、时间与演唱者，提供实际ASR词范围和边界观察依据；不能以局部词给整段手写时间盖章。
- 原始ASR可能有零时长词或重复识别；它们不自动成为有效句界。所引用的词范围必须有正时长、邻近被复核的边界。
- 全部待核及空档音乐性质须经真实音频分析解决。`production_timing_verified=true`、引擎名称、清空pending或“用户点头”均不能替代这些证据。

这些检查验证来源和复核声明的绑定，不认证声明者真正听过。当前没有可信听看服务，不提供把候选自动批准的入口；缺实际能力时保持pending，不虚构观察证据。

关1默认是生产检查，缺来源/复核就非零退出。仅结构试跑须显式 `gate_checks.py gate1 PROJECT --diagnostic`；该结果始终标记诊断用途，不能登记正式执行成功或解锁后续生产。

## 本项目的实际结果

本次重新用本机small和large-v3分别识别63.007333秒原曲；后者输出205个词记录、16行候选。两次原始结果均保留，没有因large模型更大就自动批准。真实项目现有timeline为全部待核草稿；关1已实际运行并失败。典故句和最后一句仍有识别/边界问题，未将其包装成权威时间。
