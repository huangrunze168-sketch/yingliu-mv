# 离线费用核验与交付完整性

`production_costs.audit`只核对本项目已登记作业、记录的费用响应与本地台账，不查询视频后端，不把任务完成、估价、预占或账户余额变化当作实付。

交付包必须含`cost_audit.json`；生成包和每次读取ready都会重新核验。任一登记任务仍待核费用、台账缺settle、金额/币数/供应商任务ID不符或报告过期，均不能用旧包进入ready。已丢弃样片的登记费用同样不能忽略；历史未登记费用明确保持未验证，不编造成零。

## 实付与退款

每项已结算作业须有原供应商任务ID、cash/coins原始字段指针及对应settle事件。报告分别保存记录的现金、币数和退款，不猜汇率、不从估价结账。数据一致性不等于供应商账单身份或签名认证：原费用响应必须来自实际证据，不能由Agent编写一个符合字段的数字冒充实付。

退款须关联原任务、不能超过记录实付，并提供对应原费用响应；只有负数声明不能自动冲减成本。允许有证据的纯币退款，但现金/币均不能在refund里增加。现金为0而币数为正的收费也必须先预占；release必须现金和币数都为0，避免借释放隐藏收费。

## 未派发预占

```bash
python scripts/submission_jobs.py cancel-prepared PROJECT --job-id JOB
```

此命令仅将从未派发的prepared任务先原子转成cancelled_before_dispatch，再释放本地预占；不是供应商取消或退款，不调用后端，后端禁用时仍可执行。派发与撤销竞争时，版本检查阻止在途任务被当成未消费释放。未知、派发中或已有供应商任务ID的调用不能如此撤销。

释放失败保留reconciliation_required及预占，不假报结清；重复调用可恢复同一本地释放。准备发布失败的reserve/release成对历史明确记为unpublished_preparation_released；未关联的真实收费或孤立预占仍阻断，不因没有作业文件而丢账。

## 证据范围

本地测试使用明确合成费用响应，实际运行预占、结算、释放、台账/交付包核对；不能据测试报告宣称用户已支付这些金额。当前用户明确禁止使用生成视频后端，因此本轮不通过服务查询补账，不替历史六任务估算实付。真实项目仍有其他上游缺项，不能因此ready。
