# 全 API 依赖清单与成本模型

> 技术基线：全 API 路线，Windows 本机无需 GPU。**后端门限：视频生成后端由用户自己提供，skill 只提问、不内置；但正式视频模型必须支持多模态全能参考**——未提供合格后端时流程止步于关 6 + 静帧预览成片，绝不进入批量生成。
> 所有后端走「契约先行」（铁律 D）：先拉真实节点表实测，再批量提交。

## 一、能力槽位矩阵（skill 只定义槽位，不绑定服务商）

| 槽位 | 角色 | 谁提供 | 输入 | 输出 | 验收契约 |
|---|---|---|---|---|---|
| 歌词时间戳 | ASR 对齐 | 用户提供（未提供走降级对齐，见下） | 音频 | 逐行/逐字时间戳 + 置信度 | 行级时间戳 + confidence 字段 |
| 普通镜头生成 | general | **必须用户提供** | 首帧图（可选）+ 六段式提示词 + duration | mp4 无音轨 | 时长可请求、可下载、无水印 |
| 口型镜头生成 | lipsync | **必须用户提供** | 主人公图 + 音频片段（=该段窗口裁切）+ 唱歌框架提示词 | mp4 口型随音频 | 口型与所给音频段对齐 |
| 歌词文本校正 | LLM | 用户提供（可选） | ASR 原文 + 官方歌词 | 对齐校对 + 待核行清单 | — |
| （可选）软审 | LLM 验证 | 用户提供（可选） | 首帧/成片截帧 | 画质/一致性评分 | 不替代硬判据 |

**降级路径**：无 ASR → `timeline_fallback.py` 均匀对齐（全行待核，只可试跑与静帧预览）；无视频生成后端 → `render_preview.py` 静帧预览成片。两条降级产物都明确标注「非正式成片」。

## 二、后端门限（提问清单，skill 只问不猜）

进入步骤 7/8 前，skill 一次性问清并全部拿到才放行：

1. 后端名称与接入方式（API 地址 / 节点表来源）
2. 凭证（四级读取：会话级 → 项目级 → 用户级 → 环境变量）
3. 普通镜头与口型镜头是否同一后端（决定路由表）
4. 单镜时长档位与分辨率档位
5. 并发路数
6. **真钱封顶**（元）——必填，无默认

任一项未答，流程停在该门限前；已完成的关 1–6 产物与静帧预览照常交付。

```
凭证读取顺序:
1. 会话级     （本次对话内显式提供）
2. 项目级     project/credentials.json（gitignore）
3. 用户级     ~/.workbuddy/mv-pipeline/credentials.json（跨项目永久生效）
4. 环境变量   （由后端契约决定变量名）
按序读取，取到即用；三级处缓存指纹，避免重复上传。全部未命中才提示用户，且提示一次、写入用户级。
```

## 三、成本模型（估算，以实跑台账为准）

| 项 | 单价估算 | 一支 4 分钟 MV（约 25 段） |
|---|---|---|
| ASR 对齐 | ~¥0.3/次 | ¥0.3 × 1–2 |
| 普通镜头（约 55%，14 段） | ~¥1.0/段 | ~¥14 |
| 口型镜头（约 45%，11 段） | ~¥1.5–2/段 | ~¥18–22 |
| 重抽余量（20%） | — | ~¥7 |
| **合计** | | **≈ ¥40–50/支**（实测口径见台账） |

总览页顶部三数（ledger.py 汇总）：**成片多少秒 / 机器跑了多久 / 花了多少（币与真钱分列）**。

## 四、三个独立开关（互不推定，铁律 D）

| 开关 | 含义 | 默认 |
|---|---|---|
| 账号降级 | 主账号限流/降级时是否切备用账号 | off（需显式开启） |
| 双池并行 | 两条生成车道同时开跑 | off |
| 真钱封顶 | 现金消费上限（元），达到即暂停并汇报 | 必填，无默认——**给你 key ≠ 同意花钱** |

## 五、指纹缓存

- 母带、主人公图、风格块上传一次即记 sha256 指纹；同指纹请求直接复用远端 asset id。
- 共享模板必须去参考化：提交前扫描提示词与模板中是否残留他人图/音频指纹，有则拒绝提交（防人物长相污染）。
- prompt_fingerprint：关 5 通过时签发；步 9 重抽时比对，不一致自动退回关 5。

## 六、模型中立 + 编译器

- `prompts/SHxxx.json` 保持**模型中立**的六段式，不写任何平台专属语法。
- 用户后端接入后，由其适配层把六段式编译成该后端的目标句式与参数，适配契约在步骤 7 实测并记录核对日期。
- 换后端 = 换编译器，场景母版与已锁定事实原样带走——场景事实不随后端切换漂移。

## 七、失败处理

- 在途任务先查状态再决定 salvage / 重跑，**绝不当新任务重复提交**（写进代码，不靠人记得）。
- 失败必须回挖真实原因（API 错误码 + 原始响应落 ledger note），禁止无脑重试烧钱。
- 退款/失败返还也要记台账（action=fail_refund），账实相符。

## 八、角色库与结构化 Mention 门禁

- 提示词中的 `@角色名 / @图片 N / @视频 N / @音频 N` 只是引用文字；适配层必须把它绑定到本次请求中的真实素材。
- 多模态全能参考允许直接上传图片作为人物参考；角色库、Subject Library 与全能参考图片是不同入口，不得互相冒充，也不得强制把全能参考误写成角色库审核流程。
- 每个参考素材必须声明 `handle + modality + source(asset_id/url) + intents`。人物图可承担 `character_identity + wardrobe`，并明确不继承背景、构图、灯光和姿势。
- 点名未绑定、绑定未点名用途、素材数量超过已核验 schema，均在提交前失败；禁止删除人物参考后继续生成随机人物。
- `scripts/submission_contract.py` 只校验适配层提交包，不绑定任何服务商；后端仍由用户选择。
- 参考音频只用于表演/口型条件时，适配层必须关闭生成音频，交付阶段重贴原始母带。

## 九、多模态全能参考与分时多镜

- 这是所有正式视频后端的统一强制能力，不是可选增强项。供应商可以变化，但请求必须保持 `reference_mode=omni_reference`；纯文生视频、单首帧图生视频和仅角色库模式不得作为自动降级路径。
- 全能参考的核心是组合输入文字、图片、视频和音频，并在提示词中分别说明参考人物、服装、场景、构图、动作、运镜、声音或节奏的哪一部分。
- 生成时长上限不是剪辑镜头长度。多镜生成包必须用明确时间段列出 3–5 个有叙事关系的镜头，并写出每次切换的画面触发、空间连续性和状态承接。
- 截至 2026-10-13 的模型 schema 快照：Seedance 2.5 为图片 30、视频 10、音频 10、4–30 秒；MiniMax-H3 为图片 9、视频 3、音频 3、5–15 秒。适配器每次提交前仍须重新读取实际 schema，不把这些数字固化进核心流程。
- 详细编译顺序与示例见 `omni-reference-video.md`。
